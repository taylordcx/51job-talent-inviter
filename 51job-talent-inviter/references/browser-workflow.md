# 浏览器搜索与Hi操作

## 连接和搜索

已有可用浏览器工具时直接使用它读取页面、选择岗位、填写条件和点击。不要仅因为自带脚本使用调试端口就要求用户换浏览器。按工具文档操作，不能混用不同浏览器的登录状态和元素标识。

自带脚本的备选方式：在技能目录执行下列命令，使用已启动的本机Chrome或Edge调试端口9222。读取不到端口不代表账号未登录。

```sh
python3 -B scripts/consultant_search.py jobs
python3 -B scripts/consultant_search.py template
python3 -B scripts/consultant_search.py search-browser --request request.json
```

由助手把顾问自然语言填写进请求文件，不让顾问编写JSON。`jobs`读取当次岗位选项；`job_key`从当次结果取得。多个企业端页面时通过`--target`指定正确标签页。

需要另行启动调试浏览器时，使用可见窗口、本机地址127.0.0.1、端口9222和独立用户目录`~/.51job-talent-inviter/browser-profile`，打开`https://ehire.51job.com/Revision/talent/search`。遵守执行环境的启动权限要求，让用户在该窗口完成必要登录。不关闭用户原有浏览器、不复制Cookie、不降低浏览器安全设置。

自带脚本只适配关联岗位、关键词、期望工作地、工作年限快捷选项及学历快捷选项。当前居住地与期望工作地不能互换。高级条件用实际浏览器控件补充并读回，不能传给尚未支持它的脚本后假装成功。多关键词的OR语法须当场核实；不自行拼接职位后缀。

搜索条件的具体操作、页面自动刷新与验收方法见[搜索条件与刷新核对](search-workflow.md)。涉及脚本未支持的条件时，优先全程使用 Computer Use 完成本轮搜索；不要在补完高级条件后再次运行只支持部分条件的脚本，导致报错或条件被重置。

## 每位候选人的操作顺序

1. 从当前结果卡片或详情取得候选人标识和对应职位，读取筛选所需资料。优先用页面可见简历链接或平台候选人编号识别，同名不视为同一人。候选人身份不能可靠区分时跳过。
2. 检查本地记录和页面是否已沟通。以企业账号和候选人稳定标识去重，不能仅按姓名或卡片序号。已有成功、正在处理或结果待确认的记录均不重复点击。
3. 对本轮每条必须条件逐一记录证据。满足全部条件才能行动。岗位地点、搜索筛选标签不能当作候选人自身的证据；“3年工作经验”不能证明“3年某专业经验”。
4. 点击前重新读取该候选人卡片，核对身份、条件和Hi按钮归属；检查页面可用额度，明确为0时停止。额度未知时不推测可用次数；出现额度不足立即停止，不充值、不购买权益。
5. 在本地记录中先标记该候选人为“正在处理”，再通过真实浏览器点击其卡片内部唯一的Hi／立即Hi聊按钮一次。不要全页批量选择Hi，不复用滚动或翻页前的坐标，不并行点击多位候选人。
6. 若平台弹出本次Hi的岗位选择或普通确认框，核对仍是本轮岗位、候选人和邀约含义后继续完成。涉及付费购买、交换或下载简历、电话外呼等不同动作时停止，不把它们当作普通Hi确认。
7. 等待页面响应，核实属于该候选人的新状态，例如刚出现的成功提示、已沟通状态或本次已发送的会话记录。仅打开空白聊天窗口不算已发送；仅按钮消失或点击调用返回也不算成功。
8. 成功记“已发起Hi”；明确失败记失败原因；超时、遮挡、断线或证据不足记“结果待确认”，停止继续发送并只读检查。**不得因为没有看到提示再点一次Hi**，也不得改用另一种点击方式补发。确认前保留记录，不能删除后重试。

## 执行记录

由助手在当前工作区保存专用记录文件，每次动作前后更新，后续运行读取同一记录路径。若工作区变更，应沿用已知记录位置或先核对历史，不将新文件误认为从未联系过。

最小字段：账号标识、候选人稳定标识、本轮岗位、条件及核对证据、时间、状态、结果依据。状态包括：不符合、信息不足、正在处理、已发起Hi、明确失败、结果待确认。只保存本次判断和去重所需资料，不保存整份简历或Cookie。

## 测试边界

创建或维护本技能时可用模拟页面验证流程；不得把真实候选人当测试对象。本轮没有实际岗位和筛选条件时，完成技能创建即可，不能拿参考截图的值发起邀约。上线后首次实际使用仍须读取当时真实页面，不能把搜索脚本测试通过宣称为真实Hi已经验收。
